# V2 实现说明

## 来源与实现边界

V2 需求明确了 12 道题、8 种人格、+3/+2/+1 评分结构、结果页顺序、分享归因、商品漏斗和 Dashboard 字段。

需求**没有给出**以下具体实现数据，因此仓库中明确标记为实现草案，而不是冒充需求原文：

1. 每一道题每一个选项究竟给哪几种人格加多少分。
2. 除「边界守卫者」示例外，其余人格的“校园生存技能 / 致命弱点”文案。
3. 四项娱乐指标的具体数值换算公式。
4. T 恤真实克重、成分、版型、真人尺码和真人图片。

这些内容都放在配置层，后续产品验收时直接改配置，不需要重写页面。

## 同分规则

服务端实现顺序：

1. 总分
2. 最后 4 题对应人格得分
3. 如果请求提供 `tie_choice` 且处于并列人格中，则优先用户明确选择
4. 仍并列时使用答案数组 + 人格 key 的稳定哈希作为固定种子

同一份答案重复计算时结果一致。

## 数据真实性

- 完成测试样本 `< 100` 时不展示人格占比。
- 不伪造用户数、订单、UGC、人格比例。
- 产品真实数据缺失时显示 `NEED_REAL_PHOTO / NEED_REAL_PRODUCT_DATA`，不会编造。
